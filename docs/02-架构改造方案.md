# 海外仓 WMS 架构改造方案（第一阶段）

> 目标：把"自营仓原型"改造为"多货主 3PL 海外仓系统"的地基层。
> 本文定义：数据模型、库存台账、单据状态机、目录结构、API 契约、迁移路线。
> 日期：2026-10-11

---

## 1. 目标形态

前后端分离，单体优先（勿过早微服务）：

```
┌────────────┐  ┌────────────┐  ┌────────────┐
│  web 管理端 │  │  pda 作业端 │  │ portal 货主端│
└─────┬──────┘  └─────┬──────┘  └─────┬──────┘
      └────────────────┴────────────────┘
                        │
                 ┌──────▼──────┐
                 │  api 服务   │  REST + 幂等
                 └──────┬──────┘
         ┌──────────────┼──────────────┐
    ┌────▼────┐   ┌──────▼─────┐  ┌────▼─────┐
    │Postgres │   │   Redis    │  │ 队列/Job │
    │ 主库    │   │ 锁/预占/缓存│  │ 账单/轨迹 │
    └─────────┘   └────────────┘  └──────────┘
```

**现有原型的处置**：7 个 HTML 页面不动，作为**已验收的视觉稿与交互基准**，
逐步替换为调用 API 的 SPA；`assets/wms.css` 的 design token 抽成 `@wms/ui` 包复用。

---

## 2. 三个核心概念

整个系统围绕这三个概念建立，缺一不可：

| 概念 | 含义 | 原则 |
|---|---|---|
| **Tenant（货主）** | 谁拥有这批货 | 每张业务表带 `tenant_id`，查询默认强制注入 |
| **Ledger（库存流水）** | 库存的**唯一真相源** | append-only，只追加不改不删；余额是流水的结果 |
| **Doc（单据）** | 业务动作的载体 | 每个动作 = 一次状态流转 + 一组流水写入 |

> **铁律**：禁止任何代码直接 `UPDATE inventory_balance`。
> 一切库存变化必须通过"单据状态流转 → 写 ledger → 重算 balance"完成。
> 这样才可对账、可追溯、可做财务口径。

## 3. 数据模型

### 3.1 实体总览（按域分组）

**A. 组织与权限域**

| 实体 | 说明 |
|---|---|
| `tenant` | 货主/客户（3PL 的核心维度） |
| `warehouse` | 物理仓库 |
| `warehouse_tenant` | 货主×仓库关系 + 库位共享策略 |
| `user` | 用户 |
| `role` / `permission` / `role_permission` | RBAC |
| `data_scope` | 数据范围（角色 → 可访问的仓库/货主） |
| `audit_log` | 操作审计（不可变） |

**B. 主数据域**

| 实体 | 说明 |
|---|---|
| `product` | 货主维度商品（SKU 属于货主，不同货主可有同编码 SKU） |
| `product_uom` | 商品 UOM 与换算（箱↔件↔托盘、重量、材积） |
| `packaging` | 包装规格 |
| `location` | 库位 |
| `location_tenant` | 库位的货主共享/独占配置 |
| `batch` | 批次（`product_id + batch_no`，唯一） |
| `carrier` / `carrier_account` | 承运商与账号池 |
| `channel` / `channel_auth` | 销售渠道与授权 |

**C. 库存域**

| 实体 | 说明 |
|---|---|
| `inventory_ledger` | 库存流水（唯一真相源） |
| `inventory_balance` | 库存余额（派生快照，可重建） |
| `inventory_reservation` | 订单预占记录 |
| `stock_status_dict` | 库存状态字典 |

**D. 单据域**

| 实体 | 说明 |
|---|---|
| `asn` / `asn_item` | 入库预约单（头程 ASN） |
| `receipt_task` / `putaway_task` | 收货任务 / 上架任务 |
| `qc_record` | 质检记录 |
| `outbound_order` / `outbound_item` | 出库订单 |
| `wave` / `pick_task` / `pack_record` | 波次 / 拣货任务 / 打包记录 |
| `return_order` / `return_item` | 退件单 |
| `fba_shipment` | FBA 中转计划 |
| `count_task` / `count_detail` | 盘点单 / 盘点明细 |
| `adjustment` | 库存调整单 |
| `transfer_order` | 移库 / 调拨单 |
| `exception_ticket` | 异常工单 |

**E. 计费域**

| 实体 | 说明 |
|---|---|
| `billing_rule` | 计费规则（货主 × 计费项 × 阶梯/单价/最低消费） |
| `billing_event` | 计费事件（一次作业触发一笔待计费） |
| `billing_estimate` | 作业前费用预估 |
| `invoice` / `invoice_item` | 账单 |
| `payment` | 收付款 |

**F. 集成域**

| 实体 | 说明 |
|---|---|
| `api_key` | 开放 API 密钥 |
| `webhook` / `webhook_delivery` | 推送订阅与投递记录 |
| `sync_log` | 平台/承运商同步日志 |

### 3.2 库存状态枚举

`inventory_ledger` 与 `inventory_balance` 共用同一套状态维度：

| 状态码 | 含义 | 是否计入"可用" |
|---|---|---|
| `in_transit` | 头程在途（未到仓） | ❌ |
| `in_dock` | 已到仓待收（月台） | ❌ |
| `inspecting` | 待检/质检中 | ❌ |
| `on_hand` | 在库可用 | ✅ |
| `allocated` | 已分配（订单预占未拣） | ❌ |
| `picked` | 已拣未打包 | ❌ |
| `packed` | 已打包待交接 | ❌ |
| `damaged` | 残损 | ❌ |
| `quarantined` | 隔离/冻结 | ❌ |
| `shipped` | 已发运 | ❌（转为发运记录） |
| `scrapped` | 已报废 | ❌ |

> `allocated` 与 `on_hand` 之和才是物理在库量。**当前原型只有 `avail / lock` 两个数，
> 无法支撑对账与财务口径，这是最需要先修的一条。**

### 3.3 库存流水表（核心）

```sql
CREATE TABLE inventory_ledger (
  id            BIGSERIAL PRIMARY KEY,
  tenant_id     BIGINT       NOT NULL,
  warehouse_id  BIGINT       NOT NULL,
  product_id    BIGINT       NOT NULL,
  batch_id      BIGINT,                       -- 无批次管理时为空
  location_id   BIGINT,                       -- 库位流转时必填，纯状态流转可空

  from_status   VARCHAR(16)  NOT NULL,        -- 变更前状态
  to_status     VARCHAR(16)  NOT NULL,        -- 变更后状态
  qty           INTEGER      NOT NULL CHECK (qty > 0),
  direction     VARCHAR(4)   NOT NULL,        -- IN / OUT

  -- 单据来源（一切库存变化必须可追溯到单据）
  doc_type      VARCHAR(32)  NOT NULL,        -- ASN / OUTBOUND / RETURN / COUNT / ADJUST / TRANSFER
  doc_id        BIGINT       NOT NULL,
  doc_line_no   INTEGER,                      -- 单据行号，支持一行分多笔

  -- 批次规则落地
  fifo_seq      BIGINT,                       -- FIFO/LIFO/FEFO 分配序号

  operator_id   BIGINT       NOT NULL,
  device        VARCHAR(32),                  -- WEB / PDA-07 / API
  occurred_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);

-- 对账索引：按维度重放流水
CREATE INDEX idx_ledger_replay ON inventory_ledger
  (tenant_id, warehouse_id, product_id, batch_id, location_id, from_status, to_status, id);

-- 单据追溯索引
CREATE INDEX idx_ledger_doc ON inventory_ledger (doc_type, doc_id, doc_line_no);

-- 时序裁剪用
CREATE INDEX idx_ledger_time ON inventory_ledger (occurred_at);
```

**余额表（派生，可随时 `DROP` 后由流水重建）**：

```sql
CREATE TABLE inventory_balance (
  id            BIGSERIAL PRIMARY KEY,
  tenant_id     BIGINT      NOT NULL,
  warehouse_id  BIGINT      NOT NULL,
  product_id    BIGINT      NOT NULL,
  batch_id      BIGINT,
  location_id   BIGINT,
  status        VARCHAR(16) NOT NULL,
  qty           INTEGER     NOT NULL DEFAULT 0,
  ledger_seq    BIGINT      NOT NULL,        -- 已重放到的流水序号（增量维护）
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),

  UNIQUE (tenant_id, warehouse_id, product_id, batch_id, location_id, status)
);
```

**预占表（防超卖的关键）**：

```sql
CREATE TABLE inventory_reservation (
  id             BIGSERIAL PRIMARY KEY,
  tenant_id      BIGINT      NOT NULL,
  warehouse_id   BIGINT      NOT NULL,
  outbound_id    BIGINT      NOT NULL,
  product_id     BIGINT      NOT NULL,
  batch_id       BIGINT,
  qty            INTEGER     NOT NULL CHECK (qty > 0),
  status         VARCHAR(16) NOT NULL DEFAULT 'held',  -- held / consumed / released
  held_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
  released_at    TIMESTAMPTZ,
  expire_at      TIMESTAMPTZ                               -- 预占超时自动释放
);
CREATE INDEX idx_resv_release ON inventory_reservation (status, expire_at);
```

### 3.4 货主与仓库（隔离的根）

```sql
CREATE TABLE tenant (
  id             BIGSERIAL PRIMARY KEY,
  code           VARCHAR(32)  NOT NULL UNIQUE,     -- HY-GLB-0041 风格
  name           VARCHAR(128) NOT NULL,
  type           VARCHAR(16)  NOT NULL,            -- 3PL / SELF
  contact        VARCHAR(64),
  phone          VARCHAR(32),
  currency       CHAR(3)      NOT NULL DEFAULT 'USD',
  billing_cycle  VARCHAR(16)  NOT NULL DEFAULT 'monthly',  -- weekly/monthly
  credit_days    INTEGER      NOT NULL DEFAULT 30,
  status         VARCHAR(16)  NOT NULL DEFAULT 'active',
  created_at     TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE TABLE warehouse (
  id           BIGSERIAL PRIMARY KEY,
  code         VARCHAR(16) NOT NULL UNIQUE,        -- LAX-01
  name         VARCHAR(128) NOT NULL,
  country      CHAR(2)      NOT NULL,              -- US / GB / DE
  timezone     VARCHAR(48)  NOT NULL,              -- America/Los_Angeles
  currency     CHAR(3)      NOT NULL,
  address      TEXT,
  status       VARCHAR(16)  NOT NULL DEFAULT 'active'
);

-- 货主能用哪些仓 + 库位是否共享
CREATE TABLE warehouse_tenant (
  id             BIGSERIAL PRIMARY KEY,
  warehouse_id   BIGINT      NOT NULL,
  tenant_id      BIGINT      NOT NULL,
  share_location BOOLEAN     NOT NULL DEFAULT false,  -- 允许与其他货主混放
  status         VARCHAR(16) NOT NULL DEFAULT 'active',
  UNIQUE (warehouse_id, tenant_id)
);
```

> 原型中 `settings.html` 已有"企业编码创建后不可修改"和 4 个时区——
> 这两个概念要提升为 `tenant.code` 与 `warehouse.timezone`，独立成实体。

### 3.5 主数据

```sql
CREATE TABLE product (
  id             BIGSERIAL PRIMARY KEY,
  tenant_id      BIGINT       NOT NULL,             -- SKU 归属货主！
  sku            VARCHAR(64)  NOT NULL,
  name           VARCHAR(256) NOT NULL,
  category       VARCHAR(64),
  barcode        VARCHAR(64),
  base_uom       VARCHAR(16)  NOT NULL DEFAULT 'PCS',
  net_weight_g   INTEGER,
  gross_weight_g INTEGER,
  length_mm      INTEGER,
  width_mm       INTEGER,
  height_mm      INTEGER,
  declared_value NUMERIC(12,2),
  batch_required BOOLEAN      NOT NULL DEFAULT false,
  expiry_required BOOLEAN     NOT NULL DEFAULT false,
  sn_required    BOOLEAN      NOT NULL DEFAULT false,  -- 序列号（3C/高价值）
  status         VARCHAR(16)  NOT NULL DEFAULT 'active',
  UNIQUE (tenant_id, sku)                            -- 同货主内唯一
);

CREATE TABLE batch (
  id           BIGSERIAL PRIMARY KEY,
  tenant_id    BIGINT       NOT NULL,
  product_id   BIGINT       NOT NULL,
  batch_no     VARCHAR(64)  NOT NULL,               -- B2604-0912
  produced_at  DATE,
  expired_at   DATE,                                -- FEFO 依据
  UNIQUE (tenant_id, product_id, batch_no)
);

CREATE TABLE location (
  id            BIGSERIAL PRIMARY KEY,
  warehouse_id  BIGINT       NOT NULL,
  code          VARCHAR(32)  NOT NULL,              -- A-03-12
  zone          VARCHAR(8)   NOT NULL,              -- A~F
  type          VARCHAR(16)  NOT NULL,              -- STORAGE / PICK / STAGE / RETURN / DOCK
  aisle         VARCHAR(8),
  rack          VARCHAR(8),
  level         VARCHAR(8),
  -- 原型的库位模型缺这些，导致无法做上架推荐与库容规划
  max_cbm       NUMERIC(10,3),
  max_weight_g  INTEGER,
  max_qty       INTEGER,
  mix_batch     BOOLEAN      NOT NULL DEFAULT false,  -- 是否允许混批次
  mix_product   BOOLEAN      NOT NULL DEFAULT false,
  pick_priority INTEGER      NOT NULL DEFAULT 0,      -- 拣货路径权重
  status        VARCHAR(16)  NOT NULL DEFAULT 'active',
  UNIQUE (warehouse_id, code)
);
```

### 3.6 单据统计

原型单据与目标单据统计对象：

| 原型 | 目标单据 | 关联 ledger 的状态流转 |
|---|---|---|
| ASN | `asn` → `receipt_task` → `putaway_task` | `in_transit → in_dock → inspecting → on_hand` |
| 出库单 | `outbound_order` → `wave` → `pick_task` → `pack_record` | `on_hand → allocated → picked → packed → shipped` |
| —— | `return_order`（新增） | `shipped → in_dock → inspecting → on_hand / damaged / scrapped` |
| —— | `count_task`（新增） | `on_hand → quarantined → on_hand ± 差异` |
| —— | `adjustment`（新增） | 任意状态 → 任意状态，须审批 |
| —— | `transfer_order`（新增） | `location A → location B` |
