## 1. P0 详细说明

### FIX-01 🔴 库存不扣减、预占不写锁定（最严重）

**现状**

- 全仓不存在任何 `avail -=`。库存写操作只有：ASN 上架 `+`（`actions.js:512`）、退货上架 `+`（`:826,897,1178`）、补货 `+`（`:528`）、调整 `±`（`:555,1364`）。
- 出库交接（`label`，`actions.js:578-585`）只做 `s.lock = Math.max(0, s.lock - it.qty)`，**avail 不动**；
- 预占从不加 lock：批量分仓 `oms.assign`（`actions.js:1133-1146`）只改 `status='held'` 和文案"已预占"；单条「执行预占」按钮是纯 `data-toast`（`orders.html:180`）。
- **口径本身不自洽**：多数 SKU 的 `bins.qty = avail`、`bins.lock = lock`（如 SKU-71904：5120+3300=8420=avail，180+180=360=lock），但 SKU-20865 是 `bins.qty(1610) = avail(410) + lock(1200)`。两种口径混用。

**后果**：`lock` 只减不增、`avail` 只增不减。跑几轮演示后所有 SKU 高库存、锁定归零——**库存扣减与超卖拦截两条核心闭环都不通**。

**修复方案**

1. 先定义口径（建议采用与 seed 数据多数一致的模型 A）：
   - **模型 A（分池）**：`在库 = avail + lock`；预占 `avail -= q, lock += q`；交接 `lock -= q`（货物离仓）。
   - **模型 B（子集）**：`lock ⊆ avail`；预占 `lock += q`；交接 `avail -= q, lock -= q`。
   - ⚠️ 选定后必须同步修正 `sku.release`（`:532-537` 现为 `avail += q; lock = 0`，在模型 B 下会重复计数）与全部 seed 数据的 `bins` 字段。
2. 预占落点：`oms.assign`、`order.send`、单条「执行预占」（把 `orders.html:180` 改成 `data-action`），预占前校验可用量，不足则置 `status='block'`。
3. 交接落点：`out.label` 按选定模型扣减；补 `order.send → out` 生成时的 `tenant` 字段（`actions.js:736-749` 目前漏了，初始数据有）。

**验收**：分仓后对应 SKU 库存减少/锁定增加；交接后锁定归零、在库减少；同一 SKU 连续下发超库存的订单会进入缺货拦截而非成功。

### FIX-02 🔴 确认框按钮双重执行

**现状**：`ui.js` 与 `actions.js` 各自向 `document` 挂 click 委托。点击「`data-confirm` + `data-action`」按钮时，`ui.js` 弹确认框后仅 `return`（未 `stopImmediatePropagation`，`ui.js:318-336`），同一次点击随即被 `actions.js:1534-1535` 捕获并**立即执行**；用户点"确认"后 `onOk`（`ui.js:328-330`）**再执行一次**。

**受影响的 7 个按钮**

| # | 按钮 | 位置 | 动作 | 双重执行后果 |
|---|---|---|---|---|
| 1 | 继续收货 | `inbound.html:222` | `asn:ASN-20261011-0142:recv` | 收货进度一次跳 50% |
| 2 | 批量分仓 | `orders.html:81` | `oms:*:assign` | 第二次提示"没有待分仓订单" |
| 3 | 处理缺货 | `orders.html:280` | `order:SHP-7721-0093:nostock` | 弹两次确认 |
| 4 | 批量处置 | `returns.html:81` | `ret:*:batch` | 第二次提示"没有待处置" |
| 5 | 生成账单 | `billing.html:78` | `bill:*:gen` | toast 两次（当前无数据影响） |
| 6 | 关闭波次 | `outbound.html:173` | `wave:W-20261011-005:close` | 第二次"记录不存在" |
| 7 | 清空缓存 | `settings.html:183` | `sys:reset` | **确认框未点就 500ms 后 reload**（`actions.js:1159-1162`） |

**修复方案**（二选一，推荐 ①）

1. `actions.js` 的 click 委托在处理 `data-action` 前跳过带 `data-confirm` 的按钮（把确认权完全交还 `ui.js`）；
2. 或 `ui.js` 在 `openModal` 前调用 `e.stopImmediatePropagation()`。

**验收**：7 个按钮均先弹确认、确认后**只执行一次**；取消则数据不变；`sys:reset` 只有点确认才 reload。

### FIX-03 🔴 箱数当件数入账（UOM 缺失）

**现状**：ASN `items[].qty` 单位是**箱**（抽屉表头即"箱数"，`app.js:511`；ASN-0142 四项 120+86+64+50=320=`box`），但上架入账 `s.avail += it.qty`（`actions.js:512`）把箱数直接加进按**件**计量的 `avail`。120 箱榨汁杯入账成 120 件。

**修复方案**

1. 短期：`product` 级补 `units_per_box`（箱规）字段，上架时 `avail += it.qty * units_per_box`；缺箱规时弹表单要求填写并记入明细。
2. 长期（对应 `docs/02` §3.5 `product_uom`）：建立箱↔件↔托盘换算，`avail` 统一按 `base_uom` 计量。

**验收**：ASN-0142 上架后 SKU-88231 增加 120×箱规 件而非 120 件；收货进度（箱）与库存入账（件）各自口径正确。

### FIX-04 🔴 新建 ASN 无商品明细 → 入账 0 件

**现状**：`openForm('asn')` 创建的 ASN 为 `items: []`（`actions.js:1245`），全站没有"添加明细行"的入口。这张单走完到货→收货→验收→上架，最终提示"入账 0 件"（`added=0`）。只有预置的 7 张 ASN 能真正入账。

**修复方案**：ASN 表单增加明细行编辑（SKU / 批次 / 箱数 / 箱规，支持多行），或创建后在抽屉内提供"添加明细"动作；`recv`/`putaway` 对无明细单据给出显式警告。

**验收**：页面上新建一张 ASN → 加明细 → 走完全流程 → 对应 SKU 库存按明细增加；刷新后仍在。

### FIX-05 🔴 计费链是壳

**现状**

- `bill.gen` 只 `return { msg: '已生成 14 张账单 · 合计 $184,620' }`（`actions.js:1202-1204`），**不创建/更新任何记录**；`bill.trial`（`:1188-1201`）只是汇总现有 6 张写死账单的金额。
- 「重算」「确认计费」是纯 `data-toast`（`billing.html:254-255`）；计费规则表 `<tbody>` 无 `data-render`（`billing.html:115`）；「待计费作业 1,284 笔」静态。
- 作业侧（上架/交接/换标/退货）**不产生任何计费事件**。
- 已通部分：推送 / 对账 / 提醒 / 回款（联动货主账面，`actions.js:962-998`）/ 停用。

**修复方案**（最小闭环）

1. 新增 `WMS.DB.billEvent`：上架（入库操作费）、交接（出库操作费）、换标/销毁（增值服务费）、每日仓储费四类事件，由对应 `ACTIONS` 写入 `{tenant, item, qty, amount, doc, at}`；
2. `bill.gen` 改为：按 `tenant` 聚合事件 → 生成/更新 `bill` 记录（金额 = Σ事件），不再写死 `$184,620`；
3. 规则表挂 `data-render`（新增 `billRule` 表），「确认计费」改为真实 `data-action`（幂等：已计费事件标记 `settled`）。

**验收**：跑一次入库上架 + 出库交接 → 待计费作业数变化 → 生成账单后金额由作业算出；同一账单重复生成不翻倍。

### FIX-10 PDA 页面脚本不写 DB

## 3. P2：设计约定与体验

1. **状态机分支**：ASN 缺"免检跳过、部分收货、异常挂起"的真实分支（`recv` 固定每次 +25%，`actions.js:490-499`；`inspect` 恒为"合格"，`:501-505`）。
2. **波次与出库单无外键**：`wave` 表无订单清单字段，`out` 无 `waveId`，仅靠 timeline 文案关联（`data.js:285`）——波次进度 `done` 永远不变。
3. **出库缺称重复核节点**：流程 pick→pack→label，无称重/复核（仅 `pda.html:231-232` 一句设置文案；`data.js:304` 一条 timeline）。
4. **换单号生成器**：`order.send` 的 `outSeq` 初始 3602（`actions.js:730`），刷新后从 3603 继续，但 seed 最大单号 3572，会跳号；应改用 `WMS.nextId`。
5. **多语言/多币种/多单位**：币种字段已有（`tenant.cur`/`wh.cur`）但金额展示硬编码 `$`；无 lbs/kg、in/cm 换算。
6. **权限不生效**：`usr.perms` 可编辑（`actions.js:692-710`）但无登录、无按权限隐藏、无数据范围过滤。
